# Константы для работы системы API и скриптов работы с конфиг-файлами

Здесь указаны имена, типы данных и комментарии для констант из файлов ``.env`` и ``.env.server``.

## Рабочие константы системы API

Ниже перечислены актуальные и условно-устаревшие константы файла ``.env`` - основного для файлов сборки API (кроме bash-скриптов).

> После таблицы указана важная информация о константах. Рекомендуется к прочтению.

|Имя константы|Тип данных|Описание|
|:--:|:--:|:--:|
|``HOSTNAME``|string|IP адрес сервера|
|``PORT``|number|Открытый порт сервера|
|``SUB_INDEX``|string|Буквенный индекс сервера|
|``SECRET_KEY``|string|Ключ для подписи токенов|
|``ALLOWED_IPS``|string|Доступные IP-адреса|
|``CONFIG_DIR``|string|Директория для хранения конфиг-файлов пользователей|
|``LOG_DIR``|string|Директория для хранения логов API сервера|
|``USERS_DIR``|string|Директория для хранения конфиг-файлов пользователей|
|``USER_DB``|string|Файл базы данных мета-данных конфиг-файлов|
|``CONFIG_SCRIPT``|string|Расположение скрипта для работы с конфиг-файлами|
|``ACTION_SCRIPT``|string|Расположение скрипта для выполнение действий с пользователями OpenVPN|
|``REDIS_HOSTNAME``|string|IP-адрес сервера Redis|
|``REDIS_PORT``|number|Порт Redis сервера|
|``VPN_MANAGEMENT_HOSTNAME``|string|IP-адрес для работы системы management OpenVPN|
|``VPN_MANAGEMENT_PORT``|number|Порт для работы системы management OpenVPN|
|``NO_SQL``|Boolean|Отключает SQLite из системы API|
|``NO_REDIS``|Boolean|Отключает сервер Redis из системы API|

### Полезная информация

Константа ``SUB_INDEX`` - это **обязательное** буквенное обозначение сервера. Используется для идентификации JWT-токена сервера VPN центральным сервером.

Константа ``ALLOWED_IPS`` представляет собой часть системы безопасности, ограничивающей допустимые IP-адреса для входящих запросов.

**Пример перечисления IP-адресов:**

IP-адреса перечисляются строкой через символ ``|``.

```text
ALLOWED_IPS=127.0.0.1|192.168.1.12
```
> На момент версии ``dev-2.1.8``, в случае отсутствия IP-адресов, сервер **не будет** принимать входящие запросы.

### Устаревающие или временно неиспользуемые константы

Ниже перечислены константы, временно неиспользующиеся в системе API или вовсе устаревшие:

1.  Константа ``LOG_DIR`` на данный момент не используется. Однако будет введена в работу с версии ``dev-2.1.9+``.

2. Константа ``USERS_DIR`` использовалась в версии ``1.x``. В актуальной версии (``dev-2.1.x+``) более не используется. Будет удалена в будущих обновлениях.

3. Константа ``ACTION_SCRIPT`` использовалась в версии ``1.x``. В актуальной версии (``dev-2.1.x+``) более не используется. Будет удалена в будущих обновлениях.

4. Константы ``VPN_MANAGEMENT_HOSTNAME`` и ``VPN_MANAGEMENT_PORT`` использовались до версии ``dev-2.1.5``. На данный момент не используется, но будут возвращены позже.

5. Константы ``NO_SQL`` и ``NO_REDIS`` да момент версии ``dev-2.1.8`` не используются в системе API.

### Шаблон файла (без комментариев):
```text
HOSTNAME=
PORT=

SUB_INDEX=

SECRET_KEY=

ALLOWED_IPS=

CONFIG_DIR=
LOG_DIR=
USERS_DIR=

USER_DB=

CONFIG_SCRIPT=

ACTION_SCRIPT=

REDIS_HOSTNAME=
REDIS_PORT=

VPN_MANAGEMENT_HOSTNAME=
VPN_MANAGEMENT_PORT=

NO_SQL=
NO_REDIS=
```

## Рабочие константы системы генерации конфиг-файлов и проверки соединений

Указанные ниже константы вносятся в файл ``.env.server``, и используется исключительно в ``bash``-скриптах, а именно ``ovpn-ctrl.sh``, ``inconn.sh``, ``em_backups.sh`` и ``dbinstaller.sh``.

|Имя константы|Тип данных|Описание|
|:--:|:--:|:--:|
|``OVPN_SERVER``|string|Путь до директории сервера OpenVPN|
|``OVPN_PUBLIC_HOST``|string|Необязательный публичный IPv4-адрес или домен OpenVPN-сервера. Если не указан, определяется автоматически|
|``SERVER``|string|Путь до директории сервера-обработчика API|
|``CONFIGS_DIR``|string|Путь до директории хранения сгенерированных конфиг-файлов|
|``USERDB_DIR``|string|Путь до директории хранения SQLite база данных|
|``TEMP_FILE``|string|Путь до директории хранения файла-шаблона генерации .ovpn-конфигов|

### Полезная информация

Константа ``USERDB_DIR`` хранит **путь до директории** с файлом базы данных, при этом имя файла задаётся внутри системы самостоятельно.

> В будущих версиях эта ошибка может быть исправлена.

### Шаблон файла (без комментариев):

```text
OVPN_SERVER=
OVPN_PUBLIC_HOST=
SERVER=
CONFIGS_DIR=
USERDB_DIR=
TEMP_FILE=
```

# Роуты

В данном файле указаны все доступные на данный момент эндпоинты к серверу.

> Актуально на момент версии ``2.1``. Все методы в данной версии приведены к принципам REST.

## Работа с конфигурационными файлами пользователями

Для работы с конфигурационными файлами пользователей поочерёдно, используйте эндпоинт ``/api/config``.

> Обязательно изменение **токена авторизации**: в поле ``type`` должно быть указано значение ``admin`` или ``bot``.

### Получение данных конфигурационных файлов

Для получения данных пользователя, используйте метод ``GET``:

```http
GET /api/config/:uuid
```

Где: ``:uuid`` - идентификатор конфигурационного файла пользователя.

**Пример ответа:**

```json
{
    "code": 404,    
    "data": null,    
    "message": "Configuration file not found"
}
```

### Создание конфигурационного файла пользователя

Для создания нового конфиг-файла пользователя на сервере, используйте метод ``POST``:

```http
POST /api/config
```

**В теле запроса** передаются следующие переменные:

1. ``uuid`` - идентификационный ключ конфиг-файла.
2. ``time`` - время работы конфиг-файла (в секундах).
3. ``type`` - тип конфиг-файла пользователя: _user_, _unlimit_, _unblocked_.

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "uuid": "430a8e06-d9b6-11f0-a8db-38f3ab6d0b91",
        "link": "6SM0Yj"
    },
    "message": "User configuration created successfully"
}
```

> Ключ ``link`` - идентификатор для скачивания конфиг-файла через эндпоинт ``/api/download``.

### Обновление конфигурационного файла пользователя

Для обновления конфигурационного файла пользователя на сервере, используйте метод ``PUT``:

```http
PUT /api/config/:uuid
```

Где: ``:uuid`` - идентификатор конфигурационного файла пользователя.

**В теле запроса** передаются следующие переменные:

1. ``time`` - время работы конфиг-файла (в секундах).
2. ``type`` - тип конфиг-файла пользователя: _user_, _unlimit_, _unblocked_.

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "uuid": "430a8e06-d9b6-11f0-a8db-38f3ab6d0b72",
        "link": "FD7DaT"
    },
    "message": "User configuration updated successfully"
}
```

### Обновление технических данных конфигурационного файла пользователя

Для обновления **технических данных** конфигурационного файла пользователя на сервере, используйте метод ``PATCH``:

```http
PATCH /api/config/:uuid
```

Где: ``:uuid`` - идентификатор конфигурационного файла пользователя.

**В теле запроса** передаются следующие переменные:

1. ``time`` - время работы конфиг-файла (в секундах).
2. ``type`` - тип конфиг-файла пользователя: _user_, _unlimit_, _unblocked_.

> В отличии от запроса ``PUT``, в теле запроса ``PATCH`` может передаться **как минимум один** из параметров. 

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "uuid": "430a8e06-d9b6-11f0-a8db-38f3ab6d0b72"
    },
    "message": "User configuration updated successfully"
}
```

### Удаление конфигурационного файла пользователя

Для удаления конфигурационного файла пользователя на сервере, используйте метод ``DELETE``:

```http
DELETE /api/config/:uuid
```

Где: ``:uuid`` - идентификатор конфигурационного файла пользователя.

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "uuid": "430a8e06-d9b6-11f0-a8db-38f3ab6d0b72"
    },
    "message": "User configuration deleted successfully"
}
```

## Работа с метрическими данными пользователя

Для работы с данными метрики сервера, используйте эндпоинт ``/api/server``. 

> Обязательно изменение **токена авторизации**: в поле ``type`` должно быть указано значение ``admin``.

### Информация о состоянии вспомогательных сервисов

Чтобы узнать о состоянии вспомогательных сервисов, таких, как Redis, SQLite и остальных, в том числе OpenVPN, используйте эндпоинт ``/api/server/status``.

```http
GET /api/server/status
```

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "date": "2026-07-10T17:31:12.017Z",
        "server_number": 1,
        "server_code": "nln_ru_01",
        "isServerWorking": true,
        "isRedisRunning": true,
        "isOVPNDirExists": true,
        "isConfigsDirExists": true,
        "isOVPNActive": true
    },
    "message": "Set status of all server's functions"
}
```

где:
1. ``isServerWorking`` - активен ли сам сервер?
2. ``isRedisRunning`` - активен ли Redis-сервер?
3. ``isConfigsDirExists`` - существует ли папка для хранения сгенерированных ``.ovpn``-файлов?
4. ``isConfigsDBExists`` - существует ли файл базы данных SQLite для хранения информации о конфиг-файлах?
5. ``isOVPNActive`` - активен ли сервер OpenVPN?

> Ключи ``server_number`` и ``server_code`` - это уникальные числовые и буквенные коды сервера, необходимые для идентификации данных главным сервером.

### Информация о нагрузке на физические ресурсы сервера

Для получения информации о нагрузке на CPU, ОЗУ / ПЗУ и канал связи, используйте эндпоинт ``/api/server/metrics``.

```http
GET /api/server/metrics
```

**Пример ответа:**

```json
{
    "code": 200,
    "data": {
        "timestamp": "2026-07-10T17:42:27.579Z",
        "cpu": {
            "usage_percent": 0.8,
            "avg_load": 0.01,
            "cores": 1
        },
        "memory": {
            "total_gb": 1.92,
            "active_gb": 0.45,
            "free_gb": 0.21,
            "usage_percent": 89.3
        },
        "disk": {
            "total_gb": 17.85,
            "used_gb": 7.85,
            "available_gb": 9.18,
            "usage_percent": 46.11
        },
        "network": {
            "incoming_kb_sec": 0.34,
            "outgoing_kb_sec": 0,
            "total_kb_sec": 0.34
        },
        "uptime_seconds": 57176.24
    },
    "message": "System metrics retrieved successfully"
}
```

где: 

1. ``cpu`` - данные о нагрузке на CPU.
2. ``memory`` - данные о нагрузке на ОЗУ.
3. ``disk`` - данные о нагрузке на ПЗУ.
4. ``network`` - данные о скорости отправки / получении данных (в КБ/c).
5. ``uptime_seconds`` - время работы сервера с момента последнего включения (в секундах).

## Работа с активным состоянием конфигурационных файлов

Для работы с активным состоянием конфигурационных файлов пользователя: отключением, блокировкой / разблокировкой и списком подключённых пользователей, используйте эндпоинт ``/api/active``.

> Обязательно изменение **токена авторизации**: в поле ``type`` должно быть указано значение ``admin``.

### Список подключённых конфигурационных файлов

Для получения информации о подключённых пользователях в данный момент, используйте эндпоинт ``/api/active/list`` с методом ``GET``.

```http
GET /api/active/list
```

**Пример результата:** 

```json
{
    "code": 200,
    "message": "List of active users retrieved successfully",
    "data": {
        "date": "2026-07-10T17:42:27.579Z",
        "server_number": 1,
        "server_code": "nln_ru_01",
        "count": 1,
        "active_users": [
            {
                "uuid": "430a8e06-d9b6-11f0-a8db-38f3ab6d0b72",
                "realIp": "192.168.1.92",
                "virtualIp": "10.8.0.10",
                "connectedSince": "2026-07-10T17:42:27.579Z",
                "bytesReceived": 102,
                "bytesSent": 51
            }
        ]
    }
}
```

**Описание результата:**

|Ключ|Значение|
|:--:|--|
|count|Количество подключённых пользователей|
|realIp|Истинный IP-адрес пользователя конфиг-файла|
|vurtialIp|IP-адрес пользователя конфиг-файла в системе|
|connectedSince|DATETIME подключения конфиг-файла к серверу|
|bytesReceived|Байт получено от сервера с момента подключения|
|bytesSent|Байт отправлено сервером с момента подключения|

### Отключение конфигурационного файла от сервера

Для динамического отключения конфиг-файла пользователя от сервера, используйте эндпоинт ``/api/active/kick`` с методом ``POST``.

```http
POST /api/active/kick
```

В качестве аргумента в теле запроса передаётся параметр ``uuid`` - уникальный идентификатор конфиг-файла.

**Пример успешного ответа:**

```json
{
    "code": 200,
    "message": "User kicked successfully."
}
```

### Блокировка конфигурационного файла на сервере

## Скачивание сгенерированного конфигурационного файла пользователя

Для скачивания сгенерированного конфигурационного файла пользователя используйте эндпоинт ``/api/download/`` с методом ``GET``.

```http
GET /api/download/:shortlink
```

где ``:shortlink`` - короткая ссылка, получаемая от запроса POST / PUT эндпоинта ``/api/users``.

В качестве ответа возвращает содержимое ``.ovpn``-файла.

# oVPN v 2.0 

Вторая версия коннектора от сервера с `OpenVPN` к миром посредством стандарных `HTTP`-методов, реализованных по принципам `REST API`.  

## Настройка

Данный сервис работает на основе OpenVPN. Проверьте заранее, что он установлен у вас.

В случае отсутствия OpenVPN, можете использовать скрипт автонастройки ``dbinstaller.sh`` (см. [Settings.md](docs/Settings.md)).

### Установка библиотеки

Используйте следующую команду:

```bash
git clone https://github.com/KlarDak/ovpn-server-to-bot
```

После клонирования репозитория, перейдите в него и установите зависимости:

```bash
cd ovpn-server-to-bot/

npm install
```

На этом установка всего необходимого для работы системы будет завершена.

## Настройка файлов конфигураций

Для работы сервера необходимо настроить файлы ``.env`` и ``.env.server`` - в них будут храниться константы для правильной работы сервера и скриптов-конфигураторов файлов для пользователей.

Для удобства, созданы шаблонные файлы с комментариями для каждой константы. Просто заполните их и переименуйте: уберите ``.temp`` в имени файла.

## Запуск

> Перед запуском убедитесь, что файлы ``.env`` и ``.env.server`` созданы и правильно заполнены. Без этого система **НЕ запустится**.

### Запуск ``dev``-версии

Для запуска ``dev``-версий, используйте:

```bash
npm run dev
```

### Запуск стабильной версии

Соберите стабильную версию:

```bash
npm run build
```

> Файлы ``.js`` появятся в директории ``dist/``.

После этого вы можете запускать сервис:

```bash
npm start
```

## Детали о системе безопасности

В системе работы с сервером используются некоторые решения на базе ``.env``-файла и полезная нагрузка JWT-токена, призванные усилить систему безопасности сервера.

### Секретный ключ

Значение ``SECRET_KEY`` - секретный ключ для шифрование JWT-токена. Обязательно сделайте его максимально сложным для предотвращения компрометации ключей.

### Доступные IP-адреса

Значение ``ALLOWED_IPS`` - доступные для работы IP-адреса. **Обязательно для заполнения**. Используется для ограничения выборки доступных IP-адресов для работы с системой. Соединения с адресов, отсутствующих в списке, будут обрываться.

### Типы в JWT-токене

Для разделения обработчиков используются **роли** - она делит запросы на допустимые и недопустимые, в зависимости от выбранного эндпоинта. Вся система автоматически настраивает необходимые данные.

**Пример токена:**
```json
{
  "sub": "x",
  "aud": "y",
  "iat": 2769553370,
  "exp": 2769653370,
  "role": "a",
}
```

Поля ``sub`` и ``aud`` представляют из себя буквенный индекс отправителя и получателя соответственно, то есть сервер-отправитель и сервер-получатель. Их нужно заполнить для подтверждения регистрации сервера в системе и раздделения данных между кластерами.

> **Важно:** данная информация указана для понимания системы. Все поля во время работы заполняются автоматически и с использованием данных файла `.env`. 

> С версии **2.1** поле ``type`` было убрано из-за отсутствия необходимости в них. 

## Доступные запросы

Сервер имеет несколько ``endpoint`` для работы с конфигурационными файлами, системой авторизации и данными сервера.

> API полностью реализовано по принципам REST, а значит от запроса к запросу применяются разными методы.

### Работа с пользователем

Для работы с пользователями используйте эндпоинт ``/api/users``. Через него можно получать, создавать, изменять и удалять конфиг-файлы пользователей, а также добавлять время работы и менять тип конфиг-файла.

**Допустимые параметры в теле запроса**
1. ``uuid`` - имя конфиг-файла, добавляемое в сам ``.ovpn``-файл. Данный аргумент передается **только** через метод ``POST``.
2. ``type`` - тип конфиг-файла. Может быть равен ``user``, ``unlimit`` или ``unblocked``.
3. ``time`` - доступное время работы конфиг-файла (в секундах).

### Работа с активностью конфиг-файла

Для отключения, блокировки или разблокировки конфиг-файла пользователя используйте эндпоинт ``/api/active``.

### Работа с метрикой сервера

Через эндпоинт ``/api/server`` вы можете получить информацию о состоянии сервера, его вспомогательных сервисов и нагрузке в данный момент.

### Скачивание конфиг-файла

Чтобы скачать сгенерированный конфиг-файл пользователя с сервера, используйте эндпоинт ``/api/download/:shortlink``, где ``:shortlink`` - короткая ссылка, выдаваемая сервером для скачивания конфигурационного файла.

### Скачивание без авторизации через токен

Чтобы скачать сгенерированный конфиг-файл пользователя без использования токена авторизации, используйте эндпоинт ``/getConfig/:shortlink``, где ``:shortlink`` - короткая ссылка, выдаваемая сервером для скачивания конфигурационного файла.

```http
GET /getConfig/1uiLk
```

## Доступные ответы пользователей

Шаблонный ответ следующий:

```json
{
    "code": 200,
    "data": null,
    "message": "USER_PARDONNED"
}
```

Где:
1. ``code`` - числовой HTTP-код ответа.
2. ``message`` - текстовое описание ответа.
3. ``data`` - полезная нагрузка ответа (необязательна).

Поле ``data`` может иметь разное содержимое. Специальная библиотека для работы с системой адаптирована под все виды ответов системы.
